## Intended output 1: the publish-packet Markdown document

**Path:** `pipeline/publish_packets/lena/<date>/
LENA_PUBLISH_PACKET_<slot_id>.md`

**Intended sections**, matching the real precedent's structure exactly:

1. **Header** -- status banner ("DRAFT / operator review required. Nothing
   has been posted, scheduled, or queued."), prepared date, one-line
   candidate reason.
2. **Image** -- file path, dimensions, scene description, provenance (Kling
   task id, reference-binding mode).
3. **QA summary** -- sourced directly from the real QA JSON: `overall`,
   identity/face/skin-realism highlights, public-scene-safety verdict,
   hands/anatomy/environment coherence, `hook_strength`,
   `styling_sexy_platform_safe`, wardrobe-fidelity note (diagnostic only),
   and an explicit restatement that `publish_ready: false` in QA is a
   quality verdict, not a publish authorization.
4. **Caption options** -- several (the real precedent used 5), each grounded
   in the actual scene/workorder caption, each with <=3 hashtags.
5. **Soft CTA** -- one suggested low-pressure call-to-action line.
6. **Story poll idea** (optional) -- one sticker-poll suggestion.
7. **Pinned comment idea** (optional) -- one warm/self-aware suggestion.
8. **Platform notes** -- per-platform framing (Instagram primary; Facebook/
   TikTok if relevant), crop/format guidance.
9. **Final operator approval checklist** -- explicit, unchecked boxes
   (image approved / platform-safety confirmed / caption chosen / hashtags
   reviewed / CTA-poll-pin chosen / platform+crop chosen / post time chosen
   / explicit "approved to publish" given by the operator / confirmed
   manual one-off, not batch/scheduled/auto).
10. **Notes** -- any caveats specific to this packet (e.g. reliability
    status of the generation path used).
