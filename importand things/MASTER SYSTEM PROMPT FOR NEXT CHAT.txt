5 Pipeline Contract (Stage Requirements)
Each pipeline stage is a standalone module that reads files from a defined input folder and writes outputs to a defined output folder. Each stage must:

Validate inputs on start.

Produce primary output file(s).

Produce metadata.json next to outputs with keys: source_id, node, stage, timestamp_utc, inputs, params.

Produce stage_name.status.json with keys: status (pending|running|success|failed), error (null or string), duration_seconds.

Exit with non‑zero code on unrecoverable failure.

Canonical stages

dialogue — produce script text and metadata.

tts — Azure TTS output (wav/ogg) and tts.metadata.json.

subtitle_sync — SRT/VTT aligned to audio.

compositor — 8‑layer PNG compositor output (frames or layered PNGs).

renderer — final MP4 with codecs and container settings; write render.metadata.json.

kling_stitch — optional Kling AI image2video steps.

music — Jamendo selection and license file attached.

adsguard — ad‑safety scan report; fail if unsafe.

outbox — move to outbox/pending/ with publish_request.json.

Location: nodes/ai_lady/face_cache/

PROMPT_TEXT environment variable

templates/prompt.txt

Hardcoded fallback prompt (documented in script)

File naming: immutable, timestamped, and content‑hash suffixed: <node>_face_<YYYYMMDDTHHMMSS>_<sha256>.png

Metadata: for each image write <image>.json with keys: prompt_source, prompt_text, kling_params, sha256, created_at_utc, face_id (UUID), source (kling_ui).

Append‑only: never overwrite existing files. If a generated image would collide, increment a counter suffix.

Idempotence: re‑running with same prompt must detect duplicates by hash and skip.

Encoding: UTF‑8 no BOM for all metadata and prompt files.

Error handling: fail fast with exit codes and human‑readable error messages if auth missing or Kling UI changes break selectors.

CLI: must accept --prompt, --limit N, --dry-run, --profile <playwright_profile>, --outdir <path>.
